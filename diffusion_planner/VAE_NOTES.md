# 占据栅格地图 VAE —— 改动主线与踩坑记录

> 目的:记录 `vae_map.py` 从"发糊"到"清晰可用"的每一步模型改动、决策依据和踩过的坑,
> 方便后续学习和复现。配套运行流程见 `.qoder/skills/diffusion-planner-workflow/SKILL.md`。

## 0. 任务定义

把 `64×64` 占据栅格地图(`1=障碍黑`,`0=空闲白`)编码成低维**空间隐变量**,再解码重建。
既是"大图→向量→还原"的自编码器演示,也是未来 **Latent Diffusion** 的 VAE 组件。
数据直接复用 `dataset_<M>.npz` 的 channel 0(占据),不重新生成。

---

## 1. 改动主线(时间线)

### v1 — 全局向量 latent(失败:重建发糊)
- 结构:浅层卷积下采样 64→8,`flatten` 后 `Linear` 出 **32 维全局向量**,再 `Linear` reshape 回解码。
- 结果:重建是能看出的"糊团",障碍位置基本对但边缘全糊。
- **根因诊断**:
  1. **全局 32 维向量**把"每个障碍在哪"的空间布局信息抹掉了 —— 这是主因;
  2. KL 正则的"平均化"效应进一步把细节抹平。

### 调研(相关工作怎么搭)
| 做法 | 关键点 |
|------|--------|
| Stable Diffusion / OccWorld VAE | **空间 latent**(特征图),不是单个向量 |
| eVAE (arXiv 2503.06537) | **U-Net skip**:编码器各层 concat 到解码器,找回高频细节 |
| How to train your VAE (arXiv 2309.13160) | 编解码器用 **Residual 残差块** |
| SPAN-Nav / OccWorld | 占据图重建用 **VQ-VAE** + **BCE + Lovász-hinge(IoU)** |

### v2 — 空间 latent + 残差块(引入 bug:全灰塌缩)
- 结构:`Encoder/Decoder` 逐级 64→32→16→8,通道 32/64/128/256,每级 2 个 `ResBlock`(GroupNorm+SiLU);
  latent 改为**空间 `8×8×8` 特征图**(`mu/logvar` 用卷积输出)。
- 损失:加权 BCE(`pos_weight=3`)+ KL(`β=1e-2`)。
- 故意**不加 U-Net skip**(见踩坑 3)。
- 参数量 ~**5.0M**。
- **结果:重建全灰,比 v1 还差!** —— 见踩坑 1(后验塌缩),是我改出的 bug。

### 修复 — 损失量级对齐
- 把重建从"按像素平均 `reduction=sum / numel`"改回"**逐样本求和 `sum / batch`**",与 KL 同量级。
- 结果:重建**明显清晰**,障碍块位置/大小/朝向基本对上,散点噪声小部分丢失(8×8 空间瓶颈的正常代价)。

### v3 — 调小参数量 + 加量化指标(当前版本)
- 通道参数化为 `CH=(16,32,48,64)`,参数量 **5.0M → 444K**(约 11×,权重 ~1.7MB)。
- 新增 `metrics()`:评估集(200 张,与训练不重叠)打印 **像素准确率** 与 **障碍类 IoU**。
- 冒烟测试通过(shape/loss/metrics 正常)。

## 2. 踩坑记录(重点)

1. **[最重要] 后验塌缩(posterior collapse)——损失量级不匹配**
   v2 把重建写成"按像素平均"(量级 ~0.5),KL 却还是"按 latent 求和"(量级几十~上百),
   `β·KL` 直接盖过重建 → 模型发现"把 `mu→0`、latent 不编码任何信息"最省事 → 解码器输出常数灰。
   **规律:重建项与 KL 项必须同量级**(都用逐样本求和,或都用平均)。看 loss 分项 `rec` 与 `kl` 是否被某一项主导即可判断。

2. **全局向量 latent 是发糊元凶**:占据图信息虽低,但"障碍在哪"是空间信息,必须用**空间特征图 latent**保留。

3. **U-Net skip 的取舍**:skip 能把编码器细节直接漏给解码器,重建更锐利,但会让 latent 塌缩、不再真正承载信息。
   因为后面要用 latent 接扩散,**故意不用 skip**,优先保证 latent 语义可用。

4. **β(KL 权重)与重建的权衡**:现在 β=1e-2 在求和量级下几乎可忽略 → 重建很好但 **latent 没被约束成接近高斯**。
   若接 latent diffusion,需把 β 调大(如 1e-1~1.0)重训,牺牲一点锐利度换"规整可生成"的 latent。

5. **压缩比怎么读**:`8×8×8` = 元素数压到 1/8(4096→512),但**空间面积压了 64×**(每边 8×),靠 8 通道补回。
   对比 SD VAE ~48×,8× 属**温和压缩**,对稀疏占据图足够;瓶颈在 8×8 空间分辨率(细墙/孤立点会被抹平)。

6. **可视化**:环境无 CJK 字体,中文标题会变方框 → 图内标签用**英文**;底图 `gray_r`(1=黑障碍)。

7. **日志缓冲**:`python ... > log 2>&1` 时 tqdm 的 `tqdm.write` 行是块缓冲,可能到进程结束才刷出;
   实时看进度用 `stdbuf -oL` 或直接在终端跑。

8. **GroupNorm**:`groups` 必须整除通道数;`CH` 里 16/32/48/64 都能被 8 整除,改通道时注意。

## 3. 当前配置与结果

| 项 | 值 |
|----|----|
| latent | 空间 `8×8×8`(LAT_CH=8) |
| 通道 CH | (16, 32, 48, 64) |
| 参数量 | **~444K**(v2 曾 ~5.0M) |
| 损失 | 加权 BCE(pos_weight=3,逐样本求和) + β·KL(β=1e-2) |
| 训练 | 10000 张,60 epoch,batch 64,lr 2e-4 |
